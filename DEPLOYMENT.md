# Deployment walkthrough

This project uses Vercel for the React frontend, Render for the Express API, and MongoDB Atlas for persistent data. The repository includes a Render Blueprint at `render.yaml` and a Vercel SPA rewrite at `client/vercel.json`.

## 1. Create a MongoDB Atlas database

1. Create an Atlas project and cluster.
2. Create a database user with a strong, unique password. URL-encode reserved characters in the password when placing it in a connection URI.
3. In **Network Access**, allow the Render service to reach the cluster. For a simple demo, Atlas may require an all-IP entry (`0.0.0.0/0`) because Render outbound addresses can vary. Protect access with a strong database user and never expose the connection URI in the browser. Use restricted or static egress for production data.
4. Choose **Connect > Drivers**, copy the connection string, replace the password placeholder, and use `leadflow` as the database name.

## 2. Deploy the API to Render

1. In Render, choose **New > Blueprint** and connect the GitHub repository `anjalishankar305-cmyk/AI-Powered-Automated-Lead-Qualification-and-Routing-System`.
2. Render reads `render.yaml`. Confirm the service uses root directory `server`, build command `npm ci`, start command `npm start`, and health check `/api/health`.
3. When prompted, provide `MONGODB_URI`, `GEMINI_API_KEY`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`, and `CLIENT_URL`. `ADMIN_PASSWORD` must be at least 12 characters. `JWT_SECRET` is generated by the Blueprint. Set the temporary `CLIENT_URL` to `http://localhost:5173`; replace it with the Vercel origin in step 4.
4. Deploy. Wait for the `/api/health` check to succeed, then copy the service URL, for example `https://leadflow-api.onrender.com`.
5. Visit `https://YOUR-API.onrender.com/api/health`. It should return `{"success":true,"database":"connected"}`. A 503 indicates that the MongoDB URI, Atlas network access, or database user needs attention.

## 3. Deploy the frontend to Vercel

1. In Vercel, choose **Add New > Project** and import the same GitHub repository.
2. Set **Root Directory** to `client`.
3. Use the Vite settings: build command `npm run build`, output directory `dist`, install command `npm install`.
4. Add `VITE_API_URL` with the Render API base URL ending in `/api`, e.g. `https://leadflow-api.onrender.com/api`.
5. Deploy and copy the production frontend origin, e.g. `https://leadflow-example.vercel.app`.

## 4. Connect and verify both services

1. In Render, set `CLIENT_URL` to the exact Vercel origin with no trailing slash, then redeploy the API. For more than one approved origin, use comma-separated origins.
2. In Vercel, make sure `VITE_API_URL` matches the Render API and redeploy the frontend if you changed it.
3. Open the Vercel site and sign in using the Render `ADMIN_EMAIL` and `ADMIN_PASSWORD` values.
4. Submit a test inquiry and verify that it appears on the dashboard. Check the enterprise list, details, refresh/deep links, and sign-out.
5. Confirm `/api/health` reports `database: connected`.

## Secrets and runtime behavior

- Set `MONGODB_URI`, `GEMINI_API_KEY`, `ADMIN_PASSWORD`, and `JWT_SECRET` only in Render's secret environment variables. Never put them in Vercel or variables prefixed with `VITE_`.
- Lead management API routes require an eight-hour bearer token. The UI keeps the token in session storage. This MVP supports one shared admin account; add proper user management and roles before using it for a larger team.
- The default budget threshold is 10,000 USD. Change `QUALIFICATION_THRESHOLD` and `QUALIFICATION_CURRENCY` in Render to adjust it.
- Production startup requires MongoDB and authentication settings. If MongoDB is unavailable, the API fails startup instead of silently storing leads in temporary memory.
- Render's free web service may sleep while idle, so its first request after a period of inactivity can take longer. Check Render's current plan details before relying on free hosting.
